# Brand directory — first sponsorship slice

Implemented2026-11-24. Open Sponsorship to create/search a brand, record sector/manual HTTPS website and relationship status, and link existing Person records. Each link has its own brand role and optional known start/end dates. A Person can serve several brands. Unknown dates remain empty. The website is a manual link: CRM performs no metadata/content fetch. Private Drive documents use the encrypted resource library instead.

This is partial SP1/package55/private-pilot row10. Multi-player opportunities/global and individual stages, Campaign/account foundation, offers, obligations, sponsor finance, reporting and K acceptance remain open. No employment Contract or second contact/accounting system was introduced. No automatic sending, scraping or social posting.

BrandContact stores typed Brand and Person FKs, never phone/email copies. Only live, owned parents can be linked or edited. DTOs select Person id/name only. Brand/contact edits use opening-version snapshots; parent versions also change with contact mutations/restoration. Concurrent or stale changes fail409 and preserve the form. Closed-editor responses cannot dismiss a newer draft. Each link change writes related Brand/Person/BrandContact timeline entries atomically.

Trash preserves independent Person and Brand records. Unlinking removes only the association. Re-adding a trashed association explicitly points to Trash; it never silently restores. Restoring requires both parents live and bumps the brand version. Purging a Brand removes its dependent links while preserving Persons/other Brands. Purging a Person removes only its BrandContact joins; independent Brands survive. All are covered by owner-selected retention, example dependency cleanup and encrypted recovery/checksums. Automatic business deletion remains disabled.

Migration017 creates the directory and typed joins. Append-only018 adds owner-only RLS/privileges and date-order constraint; no applied migration was rewritten. Apply the entire pending migration set before enabling the server. Neither has been applied in production. This release does not allow generic Brand file/Task/Meeting parents; later adapters must add explicit validated dispatch without widening core.delegate's Request fallback.
